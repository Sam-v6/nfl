# Repo-specific diagnosis and controlled improvement plan

## What is actually limiting the current experiment?

### Takeaway
There is concrete evidence of scarce rare-class data, endpoint/season weighting, limited input information, and incomplete convergence checks. None establishes a hard ceiling on pre-snap prediction. More independent labeled plays may help, but first measure the value of data and repair experimental comparisons.

### Inferences
- Highest-value cheap experiments: train to convergence under a fixed budget, compare uniform-row vs play-balanced sampling, add trustworthy pre-snap context/relative geometry, then preserve individual trajectories before spatial pooling. Benefits remain hypotheses.
- More unique games/rare-class plays are more useful than multiplying endpoints of the same254 2-Man plays. Existing 2022-only temporal experiments have very limited rare-class supervision.
- Calendar time, team changes, coverage taxonomy, short-vs-long history, and mixture weighting could all contribute to apparent model differences. They must not be conflated with neural architecture quality.

### Gaps
- No proof yet of label noise rate, velocity/position disagreement rate, irreducible pre-snap ambiguity, or error causes. Agent-generated interpretations of a few plays cannot establish label truth.
- No clean FP32 matched-cohort, matched-update-budget temporal comparison across multiple seeds.
- No independent fresh-game generalization evidence: old final weeks were historically exposed. Preserve those artifacts; do not use individual frozen-final mistakes to tune this next round.

## What diagnostics and ablations should run, in what order?

### Takeaway
Use an explicit experiment ledger and small conditional sequence. Preserve the old benchmark, establish development folds, and test data/sampling/convergence before expensive architecture search.

### Cited Findings
- The repository already implements chronological development folds for validation Weeks3/4/5, training on 2021 plus earlier2022 weeks; preprocessing/model refits are per fold. Reuse the principle for neural experiments with truly fold-local checkpoint selection. [Development folds](/home/sam/repos/hobby-repos/nfl/.worktrees/coverage-modernization/src/models/baselines.py)
- Learning curves can vary training-set size while retaining grouped validation. Grouped splits and `groups` are supported explicitly; our implementation must use whole games rather than random endpoint rows. [Official learning-curve API](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.learning_curve.html)
- Effective-number weighting is a published alternative to simple inverse frequency. It is an optional controlled loss arm only after diagnosis; the paper is not evidence that it improves this NFL dataset. [Original paper](https://arxiv.org/abs/1901.05555)

### Inferences
Proposed execution contract (new plan, not observed results):

1. **Freeze protocol and audit dataset.** Create v2 manifests with allowed-fit, inner-selection, outer-development, calibration, and newly acquired sealed-test roles. Keep v1 source/artifacts untouched. Group every endpoint/mirror by game. Record newly acquired unique games/plays/classes after cross-source deduplication; reject pseudo-labeled examples as evaluation truth. Compare canonical seven-class-derived man/zone with existing provider man/zone labels where present, reporting disagreement rather than rewriting labels automatically. Audit fit/development examples only for velocity vs coordinate differences, missing timestamps, left/right/mirror equivalence, coordinate scale, and class/year counts. Any velocity test must allow sensor noise and inspect systematic direction errors rather than requiring exact equality.
2. **Convergence and weighting first.** Fixed FP32 reference, matched optimizer updates/examples, seeded order. Run current30epoch schedule versus max100epochs/patience15, with checkpoint selection on inner development only. Compare uniform prepared rows, inverse-per-play row weights, and primary-endpoint-only training. Do not confound balancing with fewer SGD steps: report updates and unique plays seen. Endpoints are unavailable in2021 at early cutoffs, so sampling must be explicit. Preserve secondary -1s performance as a constraint.
3. **Equal-cohort learning curve.** For each of two forward outer-development folds (2022Week4 andWeek5), use all eligible prior data; create an inner chronological selection split from earlier weeks and keep outer fold out of early stopping. Fix one validation ID set per endpoint, original/nonaugmented only. Form nested25/50/100% subsets of eligible training *games*, stratified by season where feasible, two predetermined sampling seeds; retain every chosen game's eligible plays and parent-group augmentations. Run LightGBM and the same converged spatial configuration on the exact same training play IDs; use a fixed upper update budget and the same inner stopping rule. Report actual unique plays, games, class supports, learning curves and train/inner/outer metrics. If the25% subset lacks a class, flag unsupported class rather than resampling until favorable. For snapshot-vs-temporal comparison, separately fix the common2022 subset with required history and identical rows/masks/precision; never credit temporal model changes for different cohorts. A positive learning curve supports acquisition; a flat one motivates features/labels/model diagnosis, not a claim that more data can never help.
4. **Information ablations.** First add fields already available before the chosen cutoff: down, yards-to-go, quarter/game clock, pre-snap score differential, field position. Derive LOS/ball-relative player geometry from the observed prefix. Test orientation encoded sin/cos and relative defender-receiver positions. Track missingness and fit transforms only on training. Treat offenseFormation/receiverAlignment/personnel as unavailable at earlier cutoffs unless their timing is established; derive formation from the prefix instead of importing at-snap labels. Exclude pass result, dropback, play action, route, target, pressure, all outcomes. Team priors, if tested later, must be trained on earlier games only and checked on held-out teams/seasons.
5. **Motion representation.** Before new large architectures, compare deterministic per-player displacement/velocity summaries against snapshot on the matched2022 cohort. If useful, small per-player temporal encoder before spatial attention, stable player IDs within a play, observed-frame masking and explicit elapsed-time gaps. Do not learn player identity embeddings by default. Compare motion gains at -1s as well as -0.1s. Shuffle time order as a diagnostic only, not an augmentation, to test whether the temporal model uses chronology.
6. **Rare-class objective only if necessary.** A predeclared mild effective-number weight or a seven-class loss plus binary auxiliary loss is a testable arm, not a guaranteed cure. Preserve seven-class outputs and evaluate aggregate man probability. Do not multiply oversampling and large loss weights without an independent ablation. Avoid changing taxonomy merely to inflate score; any coarser output gets a separately named task.
7. **Confirmation and sealing.** Take at most two finalists into three-seed paired forward-fold confirmation. Select once using preregistered development rule; fit calibration afterward on its separate role, then evaluate a genuinely new compatible sealed test once. If no free compatible fresh test is obtainable, report cross-validated development improvement only, not new-game validation or automatic promotion.

Suggested screening gates: retain arms with at least +0.02 absolute macro-F1 averaged across two forward folds, no >0.01 derived-binary macro-F1 or -1s macro-F1 loss, and no >0.05 recall loss for any class with sufficient support (proposed minimum50). Always show rare-class precision/recall/support and uncertainty even below that support; lack of support is not success. Final promotion requires positive game-bootstrap lower bound versus both retained comparators plus original binary/secondary/recall gates; don't relax gates after seeing results. Gains repeated in one reused development fold do not count as independent confirmation.

### Gaps
- The source of a genuinely untouched compatible free test set is still to be established by the separate data-source research. If unavailable, that is a limit on claims, not a reason to repeatedly reopen the old final set.
- Exact inner/outer week boundaries and class minima need encoding before training, especially scarce2-Man classes. The suggested week structure is chronological but can have poor support; report and pool prespecified outer-fold predictions for descriptive rare-class estimates without breaking fold grouping.

## What budget and outcome are realistic?

### Takeaway
Budget compute to answer specific questions, not to maximize trial count. A better model is a desired outcome, not a deliverable an agent can guarantee; a valid negative result remains useful.

### Cited Findings
- Prior FP32 spatial development training took20.46seconds for30epochs; stable temporal geometry83.82seconds, while runtime records exclude some environment/preparation/startup overhead. These are small existing workloads, not estimates for expanded datasets/models. [Spatial receipt](/home/sam/repos/hobby-repos/nfl/.worktrees/coverage-modernization/artifacts/runs/spatial-fp32-training-seed42/terminal.json) [Temporal receipt](/home/sam/repos/hobby-repos/nfl/.worktrees/coverage-modernization/artifacts/runs/temporal-geometry-stable-seed42/terminal.json)
- Current frozen result and performance caveats remain the baseline record, not v2 acceptance evidence. [Maintained result report](/home/sam/repos/hobby-repos/nfl/.worktrees/coverage-modernization/docs/reports/2026-10-11-coverage-comparison/README.md)

### Inferences
- Proposed first tranche: maximum36 GPU training executions or4GPU-hours, whichever first; one job at a time; wait when user rendering leaves insufficient headroom, never kill unrelated GPU processes. Twelve GPU learning-curve fits (3sizes ×2folds ×2seeds; matching LightGBM onCPU), eight targeted convergence/sampling/feature/motion screens, twelve finalist confirmation fits (2finalists ×2folds ×3seeds), four contingency fits. Stop branches early when paired development results are flat/worse. Additional scope requires a new explicit budget rather than an open-ended Ray search.
- Log wall time including startup, epochs/updates, peak memory, processed unique plays and throughput; benchmark end-to-end preprocessing plus inference separately from prepared-tensor kernels. No training-performance goal should trade away precision/recall without disclosure.
- Useful research target: +3–5 percentage points macro-F1 on the same development protocol, improved rare-class recall without destroying precision, preservation of binary and -1s ability. These are targets, not forecasts. Do not promise80–90% seven-class accuracy from public/free data. If learning curves and feature/motion ablations plateau, stop and document the attainable task scope/data gap rather than promoting on weak evidence.
- Acquisition priority is additional verified unique labeled games and particularly scarce classes, then compatible unlabeled pre-snap trajectories for optional representation learning. Self-supervised pretraining is conditional later work, not included before demonstrating information/model bottlenecks. Synthetic mirrored/augmented/teacher-labeled plays must not be counted as new independent coverage labels.

### Gaps
No numeric expected uplift is defensible from current evidence, and no label-consistency audit has established the maximum achievable score. The plan can guarantee provenance, controlled comparisons, bounded resource use, and clear acceptance decisions; it cannot guarantee model quality.
